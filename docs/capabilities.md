# Capability registry

Each concern has one mechanism. A change that adds a second mechanism, or a helper that wraps the first, names the registry row it extends or the API it checked and the requirement that API fails (`.agents/skills/effect-design/SKILL.md`, step 5). The ruling is C46 (`docs/decisions/c46-capability-registry.md`).

## How to read a row

- **Mechanism**: the one way this repository does the concern.
- **Guard**: the lint rule keys that enforce it, as they appear in `vite.config.ts`. `none` means nothing enforces the row beyond review. `pending A<n>` names a rule that a later lint PR of work order A adds; the row keeps the marker until that rule is configured.
- **Exceptions**: the call sites or conditions the row allows, with the reason.

`tools/capabilities/registry.test.ts` fails when a guard key is not configured, or when a pending marker is not listed in the test.
